# rp-logs

## Назначение

Единый журнал экосистемы с однократной записью: любая служба, оборудование
или рабочий процесс записывает сюда «что произошло» вместо создания собственного хранилища
логов. Дешёвые записи, чтение по времени/источнику.

## Ментальная модель

Производитель отправляет событие (время, источник, уровень, текст/payload) → оно попадает в
общий поток. Потребитель читает срез по источнику или интервалу. Без
агрегации или оповещений внутри — только фиксация факта.

## Ценность для экосистемы

Один поток, повторно используемый всеми:

- Службы: операционные логи без собственного хранилища для каждого `rp-*`.
- Оборудование: логи машин/устройств — тот же API, другой источник, от 3D-
  принтеров до любого модуля или внешней системы.
- Любой производитель записывает «что произошло» в одно место вместо создания
  собственного хранилища логов; аудит и проверка читают одну временную шкалу.

## Нецели

- Не счётчики и не агрегаты.
- Не числовые выборки и не записи об использовании.
- Не трассировка распределённых вызовов и не оповещения.
## Граница ответственности

Владеет API приёма и получения логов; не владеет бизнес-метриками,
агрегацией, оповещениями или стратегией трассировки.
