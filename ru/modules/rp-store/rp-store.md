# rp-store

## Назначение

Блочное хранилище с контентной адресацией — нижний уровень бинарного хранения всей
экосистемы. Хранит фрагменты по хешу содержимого; ничего не знает о файлах,
заказах, пользователях или бизнес-сущностях.

## Ментальная модель

Производитель разбивает байты на фрагменты → помещает их в хранилище → получает
ссылки. Потребитель собирает байты из ссылок. Само хранилище — это простая таблица key(blob_hash) → байты с дедупликацией: идентичный
фрагмент, загруженный дважды, хранится один раз.

## Ценность для экосистемы

Байтовая основа с контентной адресацией:

- Непрозрачные байтовые блобы с ключом по хешу, хранятся один раз, используются везде.
- Любой производитель сохраняет байты без собственного бинарного хранилища.

## Не цели

- Не метаданные файлов и не коллекции.
- Не промежуточные записи кеша.
## Граница ответственности

Владеет записью/чтением блоков по контентной ссылке и жизненным циклом фрагментов; не владеет
именованием/коллекциями на уровне файлов и бизнес-семантикой вызывающих сервисов.
