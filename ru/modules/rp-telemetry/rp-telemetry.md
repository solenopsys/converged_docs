# rp-telemetry

## Назначение

Общий технический фид здоровья: сервисы сообщают «как они себя чувствуют» (задержка, ошибки, сигналы ресурсов) сюда, вместо того чтобы каждый ops-инструмент опрашивал их по отдельности. Нормализованный прием, единая поверхность запросов для здоровья.

## Ментальная модель

Сервис отправляет события здоровья (источник, сигнал, время, payload) → телеметрия нормализует их в единую форму. Ops-потребители (дашборды, рабочие процессы инцидентов) читают здоровье по каждому сервису во времени. Бизнес-смысл придается читателем, а не хранилищем.

## Ценность для экосистемы

Единый журнал числовых сэмплов:

- Любой продюсер записывает строки (устройство, параметр, значение, единица, время) в hot/cold-хранилища.
- Единая временная шкала для чисел любого происхождения — датчики оборудования или что-либо еще.

## Не цели

- Не хранилище текстовых логов.
- Не записи об использовании.
- Не политика алертинга и не разрешение инцидентов.
## Граница ответственности

Отвечает за прием и нормализацию телеметрических событий; не отвечает за определения продуктовой аналитики, алертинг или устранение проблем.
