# rp-events

## Назначение

Общий журнал шины бизнес-событий: любой домен публикует здесь «что произошло», не зная своих потребителей. Заказы, заявки, оборудование, платежи — все говорят на одном языке событий.

## Ментальная модель

Продюсер отправляет типизированное событие (kind, entity, time, payload) → оно попадает в общую ленту. Потребители (триггеры workflow, уведомители, аналитика) подписываются по типу и реагируют. Издатель никогда не вызывает потребителя напрямую.

## Ценность для экосистемы

Точка развязки для изменений состояния:

- Типизированные бизнес-события публикуются один раз и возвращаются списком через единый API.
- Любой домен фиксирует «что произошло», не зная своих читателей.

## Нецели

- Не сырая лента логов.
- Не счетчики и не агрегаты.
- Не само выполнение workflow.
## Граница ответственности

Отвечает за создание, хранение и получение событий; не отвечает за бизнес-обработку на стороне потребителя и выполнение workflow.
